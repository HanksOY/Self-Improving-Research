# Plain English Style (≈80% ASD-STE100)

Use this style for every answer, report, log entry and generated document.
ASD-STE100 (Simplified Technical English) is the reference. Apply it about 80%
of the way: follow the rules below, but keep the exceptions in the last section.

## Rules

1. **Answer first.** Put the result or decision in the first sentence. Do not add filler, praise or restated questions.
2. **Short sentences.** Steps: 20 words or fewer. Descriptions: 25 words or fewer. One idea per sentence.
3. **Short paragraphs.** Six sentences or fewer. Use lists for sequences and tables for comparisons.
4. **Active voice.** Write "The script writes the log", not "The log is written".
5. **Imperative for steps.** Write "Run the hook", not "You should run the hook".
6. **Simple, common words with one meaning.** Prefer "use" to "utilize", "start" to "initiate", "show" to "demonstrate", "help" to "facilitate".
7. **One term for one thing.** Do not change the name of a file, tool or concept between sentences.
8. **No idioms, phrasal verbs or slang** when a single plain verb exists ("find out" → "find", "set up" → "configure" or "install").
9. **Keep the small words.** Use "a", "the" and "that" so sentences stay clear.
10. **Limit -ing words.** Use them only as part of a technical name or where no simpler form exists.
11. **Specific, not vague.** Give numbers, file paths and names instead of "some", "various" or "a lot of".

## Exceptions (the other ~20%)

- Keep technical terms, product names, code, commands, file paths, math and citations exactly as they are.
- Keep any format that a venue, template or limit requires (paper sections, rebuttal character limits, slide templates). Inside that format, still prefer short, active, plain sentences.
- Academic papers may keep standard field terminology and hedging that reviewers expect ("we hypothesize", "suggests").
- **Never** rewrite quoted text, user messages, verbatim logs, reviewer comments or source code to fit this style.

## Subagents

When a skill or agent delegates work, it must pass this rule in the brief, so
the subagent's output follows the same style.
